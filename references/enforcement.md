# Enforcement — 交付期门禁与跨宿主契约

> SKILL.md 第 7 步「门禁回环（gate loop）」的工程细节、契约、以及
> 三条「不得」的行为规范。SKILL.md 本身只留一句产证据指令 + 指针；
> 本文件承载所有可被外置、且不应进入 SOP 层的硬约定。

---

## 1. 为什么 SKILL.md 不写这些

synthesis §4.4 给出三条理由：

1. **字符预算**——SKILL.md 当前 25,000 字符硬顶（`lint_structure`
   看护）。本文件外置后，SKILL.md 只承载「在对话里要做什么」的指令；
   工程细节、命令、错误码协议放这里。
2. **不写出来即失效的层**——本文件的存在就是「硬约束」的物证：
   agent 看到 SKILL.md 的指针，自然加载这份契约。
3. **跨宿主诚实**——synthesis §3.4/§4.2 描述的 hooks 方案是
   **Claude Code 专属**。本文件**不假设**宿主有 hooks；
   任何宿主都只看「跑脚本 + 贴原始输出 + 独立可重放」。

## 2. writing_gate.py — 交付期门禁脚本

### 2.1 调用契约

```bash
python3 scripts/writing_gate.py <draft.md> [--mode writing|judgment|meta]
```

- **`<draft.md>`** —— 必填，待交付稿件的本地路径。约定路径为
  `.sunxue/draft.md`（synthesis §4.2 落盘协议），但脚本本身不强制。
- **`--mode`** —— 选填，默认 `writing`。三档：
  - `writing` — 全部 17 项硬指标 strict
  - `judgment` — 写作技法档降为 INFO（synthesis §1.2 半可判）
  - `meta` — 仅结构档 strict，其余 INFO

### 2.2 退出码契约（synthesis §1.1 公理 4）

| exit | 含义 | 适用场景 |
|---|---|---|
| **0** | 所有 strict 项 PASS | 可交付 |
| **1** | 仅 INFO 偏离 | judgment / meta 档的「软 OK」 |
| **2** | 任一 strict 项 FAIL | 阻断，必须回 SKILL.md 第 6 步重写 |

> 注意：**当前档 ① 不会触发 exit 1**——所有指标要么 strict-PASS
> 要么 INFO-relaxed。exit 1 是档 ② 引入「软引导」时的保留通道。

### 2.3 输出契约

- **stdout** —— 逐项 `PASS / FAIL / INFO` 行 + 档 ② deferred 清单
  （6 条已知未实现指标的显式说明）。**agent 必须逐字贴出**——
  不贴 = 第 7 步未完成。
- **stderr** —— 仅在 exit 2 时输出失败摘要（专供 Stop hook 回注）；
  happy path 保持静默。

### 2.4 跨宿主强制力梯度

| 宿主 | 强制机制 | 确定性等级 |
|---|---|---|
| **Claude Code** | frontmatter hooks.Stop + 落盘协议 | exit 2 拦截（synthesis §3.4） |
| **其他宿主 / 手动跑** | 跑脚本 + 贴输出 + 用户/CI 独立重放 | 复核级（**非拦截**） |

**诚实声明**：档 ① 不实现 hooks。脚本本身是跨宿主的，强制层只
在 Claude Code 内成立。其他宿主的「可交付」= 用户看到 stdout 后
判定——这与「写完即交付」相比仍把谎报成本拉到了「必须复制粘贴
真实命令输出」的高度。

## 3. SKILL.md 第 7 步的三条「不得」（行为规范）

> 这三条原在 SKILL.md 第 7 步下，是软约束的「自律条款」。档 ②
> 引入 Stop hook 后，它们会从「自律」变「有牙的拦截」；在此之前，
> 它们是 agent 的行为规范——违反任意一条即视为第 7 步未完成。

1. **不得把自检结果抛给用户、由用户决定要不要改**——这是把质检
   外包给用户，是 skill 的失败。
2. **不得只跑一次就交付**——单次跑过的稿件仍可能漏看维度；
   必须重跑至 `exit 0` 才交付。
3. **不得跳过自检直接交稿**——这一步是必经闸门，不是建议项。

> 关联：第 8 步「致命自检 + 最后一问」是**语义层**的终审，
> 它要求第 7 步先 `exit 0`（即"第 7 步 exit 0 是第 8 步的前置
> 条件"）。语义层永不 100%（synthesis §5.2）——但「先过句法闸
> 再做语义审」的顺序是确定的。

---

## 4. 三条官方边界（不要过度承诺）

来自 synthesis §5.1，按档 ① 的诚实声明复述：

1. **触发覆盖不完备**——Claude Code `Stop` 事件无 matcher 过滤，
   是当前最稳的交付闸；但 `PreToolUse` / `UserPromptSubmit` 等
   入口门对直呼 `/skillname` 有旁路风险（hooks.md:1362）。档 ①
   不在入口设闸。
2. **Stop 熔断 8 次**——连续 8 次 block 后 harness 强制收束。
   档 ① 没有 hooks，所以该熔断路径仅在档 ② 出现。
3. **强制层对模型 ≈100%，对人不设防**——这是 hooks 的特性：
   防模型违规，不防人主动改配置。
