# 内容自洽性扫描（coherence checklist）

> SKILL.md 第 7.2 步的检查项明细。
> 这一步**不写脚本**，由模型逐项手工跑——目的是补 gate.py 看不懂的"自相矛盾"和"违反物理规律"。
> 句法闸（7.1）exit 0 之后,跑这一步;任何冲突 → 改稿 → 重跑 7.1 → 再过 7.2。**两项都通过才能进第 8 步**。

每条都按这个格式输出:

```
- [OK|FAIL] <检查项> : <证据或数值>
```

全部 `[OK]` 才算第 7.2 步通过。

---

## 1. L1 数字交叉验证

把所有 L1 数字(司龄 / 通知日期 / 补偿方案 / 用户原文出现的数字)抽出来,两两配对检查数学关系是否成立。

| 关系 | 检查内容 |
|---|---|
| 次数 × 单价 = 总额 | 例如 18 次 × 单程价 = 机票总;若不等,改单价或次数 |
| 频率 × 时长 = 总数 | 例如「每两周一次 × 3 年 = 78 次」,若文中总数 ≠ 78,改频率或总数 |
| 日期差 = 年限 | 起始日 → 终止日的日期间隔,是否与文中的「N 年/月/天」吻合 |
| 人数 × 工位 = 占用 | 例:30 个人 × 工位面积,是否在物理上能放进某个空间 |

**反例**(本任务发现):「每两周见一次」× 3 年 = 78 次,文中却写「18 次」—— 78 vs 18,差 4 倍。

---

## 2. 时间线单调性

把所有日期(年份 / 月份 / 日 / 时点)按出现顺序列出,检查:

- **单调性**:日期是否单调递增?(回忆体可以倒叙,但需明确标志,不能混乱)
- **跨度**:首尾日期跨度与文中「N 年 / 三个月」是否吻合?
- **年内合法**:2 月 30 日、13 月、24:00:60 这类非法日期要当场判 FAIL。
- **事件密度**:某个月内出现 ≥ 5 个独立大事件,需要交叉验证是否合理(如「同一天内分手 + 收到通知 + 同事告别」)。

**反例**(本任务发现):「2019 加微信 + 三年异地」实际是 4 年多,改为「2020 加微信」才能与 L1「三年」吻合。

---

## 3. 量级差真伪

SKILL.md 规则 1 / 6 要求开场有量级悬殊的对句,规则 10 要求闭环句三次量级逐次放大。**模型要算:这个量级差真的存在吗?**

| 检查 | 标准 |
|---|---|
| 数量级差 | 两个数字至少差 1 个数量级(10×),否则「悬殊」是虚胖 |
| 单位同构 | 不要拿「秒」跟「年」比,看似差 7 个数量级但语义不可比 |
| 闭环量级逐次放大 | 闭环句三次出现时,所在场景的"量"确实从小到大(一把钥匙 < 一个人 < 一套房) |

**反例**:「一年房租 1000 块 vs 一部 1.5 亿的电影」差 5 个数量级,真悬殊;「58 万 vs 7.6 万」差 7.6×,勉强,但**不**是数量级差,只能算"明显差"。

---

## 4. 物理规律 / 常识边界

故事里有动作、有空间、有物体。**模型要问:这事在物理上能发生吗?**

- **时间约束**:航班时长、签证时长、手术恢复期等,是否与文中的"几天后 / 当天 / 隔年"吻合?
- **空间约束**:人能不能在 X 分钟内从 A 到 B(地铁 / 出租 / 步行)?多远的距离要多久?
- **生物约束**:人每天最多睡 8 小时,伤口恢复要 N 天,移植器官要配型,不能 1 天完成。
- **法律约束**:离婚冷静期 30 天、合同生效条件、诉讼时效等,违反即 FAIL。
- **物件约束**:一台手机不能同时插 3 张 SIM 卡;一个钱包装不下 100 万现金。

**反例**:「早上从上海飞深圳、下午去香港、当晚回上海」,上海-深圳-香港-上海一天内技术上能完成,但需要交叉航班 + 过关,模型应判 FAIL 或要求明确写出航班号 + 过关时间。

---

## 5. 虚构项边界(白名单交叉)

如果走的是第零关·执行硬约束的"可以编"分支(详见 `writing-essence.md` §2,audit-v4 IF-10 更新指针),所有 L2 人物原型 / L3 场景首次出现时是否在白名单内?

- **L2 边界**:服务者复调段落的每个出场人物(前台 / HR / 保安 / 保洁 / 物业 / 外卖员 / 师傅 ……),必须经用户确认。
- **L3 边界**:闸机 / 工位 / 电梯 / 停车场 / 厨房 / 会议室等通用场景,首次出现需要用户授权;授权后可在白名单内复用。
- **未授权即出现 = FAIL**。

**对照清单**:写作开始前在 sidecar(草稿区)登记的虚构项清单(例如 `essay-v2-虚构项登记.md`)就是白名单;7.2 扫描时要逐项核对正文中出现的 L2/L3 是否都在白名单内。

---

## 6. 元规则:扫描报告格式

跑完上述 1-5 后,**模型必须输出**一份扫描报告,贴在 7.1 句法闸 stdout 之后、进入第 8 步之前。报告结构:

```markdown
=== 内容自洽性扫描报告 (7.2) ===
chars: <正文字数>
draft: <路径>

- [OK|FAIL] 1. L1 数字交叉验证 : <证据>
- [OK|FAIL] 2. 时间线单调性 : <证据>
- [OK|FAIL] 3. 量级差真伪 : <证据>
- [OK|FAIL] 4. 物理规律 / 常识边界 : <证据>
- [OK|FAIL] 5. 虚构项边界(白名单交叉) : <证据>

=== 总结: <PASS|FAIL> ===
```

FAIL → 改稿 → 重跑 7.1 → 再过 7.2。**两项都通过才能进第 8 步**。

## 附录:为什么这一层不放进 gate.py

档 1 的 `writing_gate.py` 用的是正则 / 字典 / 长度区间(见 `regression_output.py:284-300`),本质是字面统计。它能挡"感叹号 == 0"这种,但挡不了"18 次 / 每周 2 次"这种**需要在脑子里算乘法的矛盾**。档 2 计划把能机器化的部分(L1 数字交叉、时间线单调)抽到 `coherence_gate.py`,但**量级差真伪 / 物理规律 / 虚构项边界**这三项本质是语义判断,机器做不干净,留给模型。所以"由模型来跑"不是档 1 的妥协,是档 1 / 档 2 都成立的设计。
