# 注意力定价：要不要公开承认产品 bug — sunxue meta 层拆解

> 范例性质：meta 引擎真实调用样本
> 提问：注意力定价——产品出了 bug，管理层在纠结要不要公开承认。
> 引擎：sunxue `<!-- @mode:meta -->`（三层孙学）
> 日期：2026-09-04
> 来源：v1.2.0 实施期草稿移入 examples/，v1.2.1 audit 收口

## 一句话结论

承认 bug **不是公关动作，是资产重组**。meta 三层走完，答案不是"承不承认"，是"你有没有把它做成一个可开采的事件"。

- 准备好了 → 量半径 → 写白描 → 设计第二波 → 走起
- 没准备好 → 先对齐内部认知，发公告会反噬

---

## 文本层（被割的白描 — 怎么写）

承认公告的写法完全套 13 技法母版：

- **度量衡开场**：第 N 个用户受影响 / Y 笔交易失败 / X 小时窗口。数字先于情绪。
- **删高潮**：不写"深感歉意"。三件套：秒数 / 对方原话 / 反高潮动作。
- **闭环句 × 3**：开头「这个问题正在定位」→ 中段「已经修复 / 仍有一个边缘场景未覆盖」→ 结尾「我们自己写的代码，我们要自己改完」。
- **服务者复调**：写那个凌晨四点修 bug 的人。「他说，没事，能修。」「她改了一行配置就走了，没要钱。」
- **物件 callback**：中段慢写一行代码 / 一段日志 / 一条告警，结尾用「这一行我改了三版，现在跑得很稳」收束。

**文本层的隐性收益**：主动公开 = 你自己制造了败者位 = 拿到克制叙事的入场券。**胜者不能白描，败者才能。** Cloudflare 2022 年那篇事故复盘之所以传世，比任何"我们非常重视稳定性"的官话都有用，就因为这个。

## 系统层（赢学的生意 — 为什么做）

按 judgment 7 规则逐条过：

| 规则 | 在"承认 bug"上的应用 |
|---|---|
| **0 半径** | 产品越全球，承认的"事件规模"越大。半径没量就发 = 错配 |
| **1 买事件** | 沉默 = 租广告（每次都要续费；负面一旦爆出全部失效）。公开 = 买断事件 |
| **2 设计第二波** | 承认 / 修复 / 复盘 / 技术博客 / 行业分享。**只想到第一波就别发** |
| **3 塞进已知名单** | 参考 Cloudflare 2022 / Vercel / AWS 同量级事故的承认姿势 |
| **4 坏名声比没名声好** | 沉默 = 负向资产（谣言版越传越离谱）；承认 = 负转正 |
| **5 公开冲突反用** | 你的对手不是用户，是沉默的成本。主动披露 = 主体；被迫披露 = 被告 |
| **6 一千天** | 首次发现到首次被人公开提起的窗口期。晚一天，价值差一个数量级 |
| **7 傲慢最先被清算** | 「是用户没按文档用」这句话一出口，清算就开始 |

**关键算账**：今天承认 = 一次性付清「承认成本」+ 买到一个「未来三年叙事主导权」的资产。**沉默拖一天 = 未来复盘里多一行"我们当时为什么没早说"。**

## 修行层（破戒的代价 — 做完怎么活）

承不承认这个决策背后有三种傲慢：

1. **「我以为能藏住」** —— 藏住的成本比承认高十倍，被发现时承担两次伤害。
2. **「承认 = 示弱」** —— 2020 年以前的肌肉记忆。示弱的勇气才是资产。
3. **「先看市场反应再说」** —— 把决策权外包给市场，市场会给你最差的方案。

**带「我输了」心态去承认 = 把好事做成事故。** 先修内心，再修代码，最后修公告。

---

## 待补三参数（决定具体走位）

骨架不挑产品，但执行参数决定走哪条路：

1. **产品是什么** → 量半径（社区 thread / 致用户信 / 行业发布 / 公开复盘）
2. **影响面多大** → 定事件规模（用户数 / 交易数 / 时长 / 是否涉及数据安全）
3. **首次发现到现在多久了** → 看窗口（主动披露 vs 被迫披露）

补完这三项，骨架就能落到具体动作。

## 附：与 writing / judgment 模式的关系

本次拆解纯 meta（文本 / 系统 / 修行），未进入：
- **writing 引擎**：因为本任务不是写散文，是做判断。**严禁**用 writing 引擎把这次承认写成营销稿。
- **judgment 引擎**：本笔记的"系统层"段已借用 judgment 7 规则做对照，但严格来说 judgment 用于"该不该花钱买事件"——本次是"是否免费重组既有负向资产"，性质不同，所以判 judgment 不直接适用，只借用规则集。

**结论仍然以 meta 修行层为最终裁定**：技术问题可解，心理问题不可解。"承不承认"是个心理问题，"怎么承认"才是技术问题。
